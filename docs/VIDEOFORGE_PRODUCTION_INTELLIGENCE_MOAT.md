# VideoForge — Production Intelligence Moat

## Purpose

VideoForge is not positioned as a generic prompt-to-video application. Its durable product layer is the production intelligence that sits above interchangeable generation providers.

## Core system

MUSIC → STORY → VISUAL DNA → CANON → CHARACTERS/WORLD → SHOT PLAN → MOTION → PROVIDER STRATEGY → GENERATION → EVIDENCE → QA → REPAIR → CONTINUITY → TIMELINE → MASTER

The generation model is replaceable. The production intelligence is the product.

## Differentiating subsystems

### 1. Music intelligence
The mastered audio is the timing source of truth. Analysis produces BPM, beats, downbeats, bars, sections, energy, onsets, vocal events, and lyric timing.

### 2. Visual DNA
Each project has an explicit visual identity covering look, lighting, lens/camera language, texture, motion language, recurring motifs, section shifts, lyric mapping, identity locks, and never-show constraints.

### 3. Hierarchical canon
Canon is resolved through GLOBAL → CHARACTER → WORLD → SCENE → SHOT. Lower-level instructions cannot silently overwrite locked higher-level creative decisions.

### 4. Continuity graph
Approved shots create reusable state references for character, wardrobe, location, visual DNA, lighting, screen direction, camera, action, and props. Continuity is evaluated between actual neighboring generations, not inferred from prompts alone.

### 5. Motion specification
Motion is represented independently from appearance. A shot can specify motion type, style, tempo, beats, acceleration, recovery, stance, and timed action beats.

### 6. Provider capability routing
Generation strategy is selected from explicit provider capabilities rather than hardcoding one model. The same production plan can route different shots to different capable providers.

### 7. Evidence-first QA
Unknown is not pass. Technical, visual, temporal, continuity, and timeline evidence must be available before a real artifact can be approved.

### 8. Repair routing
Failures become structured repair directives. Identity drift, anatomy, temporal instability, composition, background drift, timing, and technical failures route to targeted repair actions instead of indiscriminate regeneration.

### 9. Production provenance
Every generation records provider, model/version, prompt, negative prompt, seed where supported, parameters, references, artifact metadata, QC, and version history.

### 10. Artist Impact Layer
The system can identify observable opportunities for reusable cuts, communication hooks, calls to action, products/services, and platform variants without making unsupported virality predictions or forcing brand placement.

## Product principle

VideoForge should use the best available generation models rather than attempt to outspend model vendors.

The moat is the system that decides:

- what should be generated;
- why it should be generated;
- which references and locks must survive;
- which provider is appropriate;
- whether the result is actually acceptable;
- what failed;
- how it should be repaired;
- how approved shots relate to one another;
- and how everything becomes a finished master.

## Evidence standard

Development simulation may use explicit simulated artifacts.

Production approval requires inspectable evidence. Missing measurements are UNKNOWN and cannot silently become PASS.

## Benchmark discipline

The 10-video / 48-hour objective is a benchmark target, not a product guarantee. Production readiness must be demonstrated through representative projects, torture cases, human-labeled evaluation, repair experiments, regression tests, cost measurements, and wall-clock measurements.

## Strategic rule

Do not chase feature parity with individual AI video products.

Continue building the production-control layer that can orchestrate whatever generation models are strongest at the time.
